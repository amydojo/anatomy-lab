## Failure classification and repairs

Original desktop run [41100464666](https://github.com/amydojo/anatomy-lab/actions/runs/41100464666) at ab1a87d: 164 passed, 7 failed. Mobile Chromium and WebKit each had 162 passed / 9 skipped. All seven desktop failures were in the same-test neutral-image comparison. Downloaded artifact 12997763345 contains 14 initial/retry before/after pairs; all were decoded independently. Every camera/UI state matched. Every changed pixel lay in the native range-control edge, a 4-by-8 pixel area; anatomy did not drift. This is a composited screenshot capture issue, not a stale golden baseline.

Final fixture redraws and reads the real WebGL specimen buffer synchronously because preserveDrawingBuffer is false. It asserts that capture leaves camera, region, motion, secondary angle and layer unchanged; rejects flat/cleared images; requires primary/secondary motion to change specimen pixels; and requires every decoded specimen pixel to match on neutral reset. Visible sliders and degree labels must independently be zero. No tolerance, masks, replacement baseline or weakened neutral assertion.

Those stronger UI checks exposed a real mobile defect: the engine reset to zero while a visible slider remained at 20. Commit c1be15c0ae3c2993aa1f0e6e7331a26d9c636d56 observes both shared motion outputs and updates the mobile adapter when either cached angle differs. This fix remains in the final RC.

A camera timing trial stretched low-frame-rate return transitions and was rejected. Final commit 5eff540 restores camera runtime and desktop slider styling exactly to ab1a87d, and samples continuity via native RAF timestamps instead of a timer measured after blocking WebGL draws. Original 1500ms sample window, completion and movement bounds remain unchanged. The helper-only unit test for the removed trial helper was also removed; source tests return to 35.
