# GRAVITY V15.9.4 — experimental camera policy
Baseline 6d51fc01364afdb647064bf9ddc0fae36c17cdbf. Opt in with &gravity=1 on an existing Expedition URL; &gravityHaptics=1 additionally enables best-effort short selection rumble. Omit both for the original interaction. Standard L3 (button 10) is held for quarter-speed precision; all existing commands and stick curves remain. No new modes, automatic camera motion, streaming edits, source transforms or physical-unit assertions.

## WORLD boundary
The injected synchronous provider exposes inspectionPoint(camera) -> {x,y,z} in the camera's current display coordinate space or null. It must not load geometry, scan triangles or mutate the camera. Current adapter reuses a user-selected exact source point, only while its part is visible and (where provided) rendered. Future WORLD providers should additionally associate immutable world/space ID, geometry revision and landmark identity; invalidate on coordinate-space change. Missing or stale data must return null. Geometry updates alone must never cause camera movement. Existing continuum D-pad landmark travel and R3 fit/retry remain explicit; legacy disconnected region changes retain their current fit behavior.

The camera is projective with fixed virtual eye depth 7.4; zoom changes projection scale, not physical distance. Selected, visible surface point remains at its prior screen pixel during zoom/orbit, unless camera target would exceed existing bounds or user pans. Close inspection reduces pan speed using target-to-point display distance and zoom, not anatomical clearance. No physical collision or surface following is enabled. Future optional surface query should return a qualified closest point, normal, distance, space ID and confidence or null; use bounded asynchronous/cache updates and require explicit activation before tangent constraints. Do not infer normals or collision from AABBs. Existing touch/pinch/pointer pathways and orientation HUD are untouched. Physical touchpad coordinates are not exposed by the standard Gamepad mapping; do not bind vendor axes or request WebHID. Optional haptic uses playEffect('dual-rumble') with no support requirement; no confirmation of physical vibration.

## Acceptance
Run npm test, including v15-gravity.test.mjs, and existing browser checks. Test simulated controller separately from hardware. Physical A/B: identical device, region, optical mode, viewport and display route; compare active callback intervals, CPU submission, selection CPU, neutral drift, L3 precision, zoom anchor, pointer coexistence and reconnection. Existing diagnostics export via expeditionDiagnostics=1. GPU/presentation and physical latency are not measured by CPU callback proxies. Test selected anchor disappearing or world identity changing and explicit recovery; no camera jump without user motion. AirPlay and iPhone acceptance remain physical gates. No production promotion.
